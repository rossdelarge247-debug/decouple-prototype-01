## What to build (spec changes, in order of need)
1. **`/help`, a new public page (§1, §2, §4.1, §4.5).** Rewrites to `Marketing 03 · Help & Support.html`, like `/privacy`. It loads `help/help.css`, `help/help.js`, and fetches `help/help-sources.json` and `help/help-content.json` by script, so add both JSON files to `_public.json` (§5.6).
2. **Help content in the build (§5.2, new).** Read `site/help/help-sources.json`, fetch each listed path from `https://www.gov.uk/api/content<path>`, clean the body to the allowed tags, list the forms from the financial remedy forms collection, and write `dist/help/help-content.json`.
   - A path that doesn't exist fails the build by name. Paths marked `"confirm": true` (today only `/council-tax`) warn instead; list them in the handoff.
   - If GOV.UK can't be reached, reuse the live `https://decouple.uk/help/help-content.json`; failing that, write an empty `pages` object. The page never empties: it falls back to links.
3. **Weekly refresh (§7, §9):** `GET /api/cron/rebuild`, called by Vercel Cron (`0 5 * * 1`) with `CRON_SECRET`; it calls `DEPLOY_HOOK_URL`. New variable `CRON_SECRET`. Publish in Site settings refreshes it too.
4. **Search (§4.5, §5.1, §5.9):** with `indexing` on, `/help` loses the noindex header, joins the sitemap (with `lastmod`) and gets `Allow: /help$`. Canonical `https://decouple.uk/help`.
5. **Build details (§5.5):** cache-bust `<link rel="prefetch">` too (the help page names `shared/dc-site.js` that way and loads it only when someone signs up). Serve `help/*.json` with `no-cache`.
6. **Tracks (§4.4):** new token `m08` → `MVP 08 · Help & Support.html`; `mvp` now means all nine MVPs. Optional alias `/p/mvp08`.
7. **`/api/signup` (§7):** new source `help`.
8. **§11 check 13** for the above.
