Replaces `site/` entirely, following `SYNC.md`. The spec changed, so `docs/SITE-SPEC.md` is included. PR name: `sync: design export 2026-10-14d`.

Exports `2026-10-14b` and `2026-10-14c` were never landed. This one supersedes both and includes their changes. `EXPORT.json` names `2026-10-14a` as previous.

## What to build (spec changes, in order of need)
1. **§7 `/api/answers`: accept the new test names.** Besides the three existing values, `test` may be `Screener`, or match `^MVP \d{2} · [A-Za-z&' -]{1,40}$`. Without this, every MVP and screener answer gets a 400. Each value gets its own tab (§6).
2. **Tester codes get a track (§3, §4.4, §6, §7).**
   - Codes have two new fields, `track` and `mode` (new columns on the Codes tab; `/api/admin/codes` accepts and returns them).
   - A tester whose code has a track may open `/take-part`, the prototype pages in that track, and `proto/`, `mvp/`, `shared/`, `take-part/`. Nothing else: the hubs are always owner-only.
   - `/api/session` returns `track` and `trackMode` for testers.
   - **`TESTERS_CAN_OPEN_PROTOS` is retired.** Remove it.
3. **`/take-part` (§2, §4.2, §8):** rewrites to `Decouple · Take Part.html`.
   - `?code=` works as it does on `/`.
   - With no session it shows a small code page (you build it, like `/studio`), never a 404.
4. **`/api/participant` (§7, new), and a `Participants` tab (§6):** the thank-you step's follow-up and voucher email. It is never returned by any read, and never stored alongside answers.
5. **`/api/claude` (§7, §9, new):** the AI proxy, with limits, a monthly spend cap and no content logging.
   - §9 adds `ANTHROPIC_API_KEY` (a new key), `CLAUDE_MODEL` and `CLAUDE_MONTHLY_CAP_USD`.
   - `shared/dc-site.js` already calls it on the site. Until it exists, the AI features say they're unavailable.
6. **Optional aliases** `/p/mvp00` … `/p/mvp07` (§2), which redirect like `/p/01`. **MVP 00 · Public Site is a prototype, not a public page.** `/` and the public allow-list don't change.
7. **§11: checks 10–12** for the above.
8. **§4, §5.1, §7 (from 14b):** the search-engine setting `indexing`, robots.txt, the sitemap, canonical links, and minifying all JS and CSS.

## How the MVP pages behave (nothing to build)
- No account to use any tool. **Saving is simulated in the browser only.** No account, email or `/api` call is made.
- Fake-door, pay-screen, rating and save events are normal answer rows on that MVP's tab (`qid` like `fd-bank`, `pay-disclosure`, `ask-rate`, `signup`; `price` = the price shown). They're sent only in testing mode, with the existing consent.
- **No payment is ever taken** and no card details are asked for. The "Right for us?" answers are never sent: only the result band.
- No new fonts or outside scripts. New outbound links are plain `<a>` links to gov.uk, Family Mediation Council, MoneyHelper, Citizens Advice, Cafcass and Resolution.
